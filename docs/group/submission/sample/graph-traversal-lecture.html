Why traverse a graph?

  • Many questions about a graph begin with "which vertices can I reach from here?"
  • For example: Is the graph connected? What is the path with the fewest edges from s to t? Does the graph contain a cycle? How many connected components does it have?
  • A traversal from a source vertex s visits every vertex that can be reached from s, each exactly once.
  • BFS and DFS are the two standard traversals. They differ only in which discovered vertex they deal with next.

The one idea both traversals share

Mark a vertex as visited the first time you reach it. Never visit a marked vertex again.

  • Without the mark, a traversal would go round a cycle for ever: in H, P → R → S → T → P → R → …
  • With it, each vertex is handled at most once. This is also why both traversals are fast (slide 10).
  • We store the marks in an array visited[v], and record who reached v first in parent[v].

Breadth-First Search (BFS)

The idea: explore in layers, nearest first

  • First the source s, then every vertex one edge from s, then every vertex two edges from s, and so on.
  • Vertices that have been discovered but not yet processed wait in a queue: first in, first out.
  • dist[v] is the number of edges from s to v; parent[v] is the vertex that discovered v.
  • A vertex is marked when it is enqueued, not when it is dequeued, so it never enters the queue twice.
BFS(G, s):
    for each vertex v: visited[v] = false
    visited[s] = true
    dist[s] = 0;  parent[s] = none
    Q = empty queue;  Q.enqueue(s)
    while Q is not empty:
        u = Q.dequeue()
        for each neighbour v of u, in order:
            if not visited[v]:
                visited[v] = true
                dist[v] = dist[u] + 1
                parent[v] = u
                Q.enqueue(v)

"In order" means alphabetical order in this lecture.

BFS finds shortest paths in an unweighted graph

Claim. On an unweighted graph, the first time BFS reaches a vertex v, the path it has found from s to v (follow parent[] back to s) uses the fewest possible edges. So dist[v] is the shortest distance.

The idea of the argument

  • The queue is first-in first-out, so every vertex at distance d leaves the queue before any vertex at distance d + 1.
  • So vertices are discovered layer by layer: all of layer d before any of layer d + 1.
  • So v is first reached from a vertex one layer nearer to s, and its path has exactly dist[v] edges.

The full argument is an induction on the distance; try it in the tutorial.

This fails when edges have different weights: a path with more edges can have a smaller total weight.

H drawn in BFS layers from P. Every edge joins two vertices in the same layer or in neighbouring layers; none skips a layer.

Depth-First Search (DFS)

The idea: go as deep as possible, back up when stuck

  • From the current vertex, move to its first unvisited neighbour, and carry on from there.
  • When the current vertex has no unvisited neighbour, back up to the vertex you came from and try its next neighbour.
  • In the recursive version, "backing up" is simply a call to DFS returning. The recursion remembers the way back.
  • The edges u–v with parent[v] = u form the DFS tree.
DFS(u):
    visited[u] = true
    for each neighbour v of u, in order:
        if not visited[v]:
            parent[v] = u
            DFS(v)
To start from s:
    for each vertex v: visited[v] = false
    parent[s] = none
    DFS(s)

"In order" means alphabetical order in this lecture.

  DFS(R): P visited; Q not visited, call DFS(Q)

Order of first visits: P, R, Q, U, T, S

Thick edges: the DFS tree. Dashed: P–T and R–S, not in the tree.
  • Tree edges: P–R, R–Q, Q–U, U–T, T–S. H is connected, so the tree has V − 1 = 5 edges.
  • Not in the tree: P–T and R–S (7 − 5 = 2 edges).
  • In an undirected graph each such edge joins a vertex to one of its ancestors in the tree, so it is a back edge: P is an ancestor of T, and R is an ancestor of S.

Running time with an adjacency list: O(V + E)

  • Vertices. Every vertex is marked once and processed once (dequeued in BFS, or given its one call in DFS): O(V).
  • Edges. Processing u scans u's adjacency list once. Each list is scanned once in the whole run, and in an undirected graph every edge appears in two lists, so the lists have total length 2E: O(E).
  • Total: O(V + E), for both BFS and DFS.
  • With an adjacency matrix, finding the neighbours of one vertex means reading its whole row: O(V). Doing that for all V vertices gives O(V²).

Check on H

V = 6, E = 7. The list lengths are 2 + 2 + 3 + 2 + 3 + 2 = 14 = 2 × 7.

Modelling a problem as a graph

The recipe: four questions

  1. What are the vertices?
  2. What are the edges?
  3. Directed or undirected?
  4. Weighted or unweighted?

Then ask which question about the graph the problem is really asking, and pick the algorithm that answers it.

Example: fewest flights between two cities

  • Vertices: the cities.
  • Edges: a direct flight between two cities. It runs in both directions, so the edge is undirected.
  • Unweighted: we count flights, not kilometres or hours.
  • Algorithm: BFS from the origin city. dist[destination] is the fewest flights, and following parent[] back from the destination gives the route.
  • Cost: O(V + E), with V cities and E direct routes.

If we wanted the least total flying time instead, the edges would carry weights and BFS would no longer be correct.

Summary

  1. Both traversals mark a vertex the first time they reach it and never visit it twice.
  2. BFS uses a queue and explores in layers, nearest first.
  3. On an unweighted graph, BFS finds paths with the fewest edges: dist[v] is the shortest distance.
  4. DFS goes as deep as possible and backs up when stuck, using recursion or an explicit stack; in an undirected graph, the edges it leaves out of its tree are back edges.
  5. With an adjacency list, both run in O(V + E); with an adjacency matrix, in O(V²).
